# استعمال GitHub في هذا المشروع

## القيد الأساسي
الذكاءان المساعدان (نسخة مجانية) **لا يصلان إلى GitHub**. لذلك GitHub هنا لـ: نسخة احتياطية، تاريخ كامل، تشغيل الاختبارات آلياً (CI)، ومراجعة التغييرات. أما العمل مع الذكاء الآخر فيجري **بالنسخ واللصق** عبر أداتين:
- `node tools/task-packet.js T-001` ← يبني `packets/T-001.txt` (القواعد + المعمارية + البطاقة + محتوى الملفات المسموحة) تلصقه كاملاً في الذكاء الآخر.
- `node tools/apply-reply.js T-001 reply.txt` ← يطبّق ردّه **بأمان**: يقبل فقط الملفات المسموحة، يأخذ نسخة احتياطية، يشغّل الاختبارات، ويستعيد كل شيء إن فشلت أو **قلّ عددها** (حتى لا «ينجح» بحذف اختبارات).

## حفظ ردّ الذكاء الآخر في ملف

    cat > reply.txt << 'ZZZZ'
    (الصق الرد كاملاً هنا)
    ZZZZ

(استعمل ZZZZ لا EOF، لأن الرد نفسه يحوي EOF)

## الإعداد (مرة واحدة)
1. أنشئ مستودعاً فارغاً على github.com (خاص أو عام) بلا README.
2. أنشئ **توكن**: Settings ← Developer settings ← Personal access tokens. للتوكن الدقيق (fine-grained): صلاحيات Contents (قراءة وكتابة) و**Workflows** (كتابة، لأننا ندفع ملف CI)، و Pull requests/Issues إن أردت. للكلاسيكي: نطاقا `repo` و`workflow`.
3. `bash tools/gh-setup.sh https://github.com/USER/REPO.git` — كلمة المرور عند الطلب = التوكن.

## ملاحظات
- **خاص أم عام؟** على الخطة المجانية لا تُفرَض قواعد حماية الفروع على المستودعات **الخاصة**؛ يعمل CI ويُظهر ✓/✗ لكن لا يمنع الدمج. والمستودع **العام** يدعمها. وإن كان عاماً أستطيع قراءة ملفاته وفروقات PR من الرابط مباشرة (`.../pull/N.diff`)، أما الخاص فتلصق لي `git diff`.
- لا تضع التوكن في ملف ولا في محادثة. إن تسرّب فاحذفه من GitHub فوراً.
- الدفع الأول يرفع المشروع بلا `node_modules` ولا النماذج `.glb` (مستثناة في `.gitignore`)؛ الحجم عادة صغير، ويطبعه السكربت قبل الدفع.
- التدفق بدون ذكاء ثانٍ: فرع `t/T-xxx` ← التعديل ← `node tests/run.js` ← `git push -u origin t/T-xxx` ← فتح Pull Request على الموقع ← CI ← الدمج.
